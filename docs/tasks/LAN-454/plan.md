# LAN-454 장기기억 추출 hotfix 검증 기록

- 기준: `origin/main`의 `36715a6214e535924632476cf1be9800b24f2cfc` (`ai-v1.3.0`).
- 작업 브랜치: `hotfix/LAN-454`.
- 상태: 시간대 변환까지 구현·검증했으나 실제 LLM 품질 실패가 남아 Draft PR만 생성한다. 병합·배포 보류.
- BE·공개 DTO·DB 스키마는 변경하지 않는다. 운영 기억 정리와 USE 활성화도 실행하지 않는다.

## 변경

1. 청자인 캐릭터를 현실 사건의 참여자로 추가하는 EPISODE 지시를 수정한다.
2. USER 원문에 캐릭터 이름이나 직접적인 상대 지칭이 없는 EPISODE 및 캐릭터 추가 후보를 임베딩 전에 제거한다. 남은 후보는 인덱스를 재정렬한다.
3. 일회성 의도·과거 활동을 PROFILE로 승격하지 않고, 유용하고 근거 있는 사건은 EVENT로 보존한다.
4. 불분명한 전사·불확실한 자기평가·미확인 건강 추측은 추출하지 않도록 지시한다. 혼합 발화의 독립적인 확정 사실은 보존한다.
5. 다른 사건의 날짜를 옮겨 쓰지 않도록 지시하고 extractor를 `memory-candidate-v7`로 구분한다.

## 검증 순서와 증거

- 운영 원문을 fixture에 복사하지 않았다. 사건·인물·상태를 바꾼 합성 발화만 모델에 보냈다.
- 먼저 캐릭터 오삽입과 재인덱싱 API 테스트를 추가했다. 수정 전 3개 테스트 중 하위 사례 5개가 실패했고, 명시적 공유 대화의 보존 사례는 통과했다.
- 수정 후 프리톡 API 137개 통과, 전체 unittest 472개 실행·7개 skip·실패 0개.
- unittest의 LLM·embedding은 mock이다. 실제 LLM 평가는 별도 스크립트로 실행했고 embedding·DB 저장·사용자 대화 생성은 호출하지 않았다.
- 실제 모델: OpenRouter 설정의 `openai/gpt-5.4-mini`, temperature 0. 공급자 라우팅은 고정하지 않았다.
- 자동 검사는 후보 수·유형·필수/금지 표현과 서버 계약을 검사한다. 의미 정확도나 운영 Precision 추정값이 아니다.
- 첫 수정은 기본 사례 32/32와 추가 사례 10/10을 자동 통과했지만, 수동 검수에서 공개일을 시청일로 옮긴 오류를 발견했다. 추가 사례의 기대값을 강화하고 이후 검증에서 실패로 처리했다.
- 날짜 규칙과 대조 예시를 두 차례 보완한 최종 응답은 공개일을 시청일로 옮기지 않았다. 그러나 날짜 불명 시청을 EVENT로 저장하며 validFrom에 발화 시각을 넣고, 프로그램 공개 소식도 별도 기억으로 저장했다. "근거 없는 과거 EVENT 시각 대신 후보 제외" 기준은 2회 모두 미충족이다. 최초 오류와 최종 미충족을 구분해 기록하며 추가 프롬프트 조정은 멈춘다.

최종 수치와 재현 가능한 합성 응답은 아래 평가 결과 파일에 보관한다. 각 파일에는 모델·시각·프롬프트 및 사례 파일 SHA-256을 포함한다.

| 평가 | 파일 | 결과 |
| --- | --- | --- |
| 수정 전 기본 16개 × 2회 | `before.json` | 30/32 자동 통과 |
| 최종 기본 16개 × 2회 | `after.json` | 32/32 자동 통과 |
| 추가 5개 × 2회 | `holdout.json` | 8/10 자동 통과, 날짜 불명확 시청 사건 2회 실패 |

## 재실행

외부에서 `OPENROUTER_API_KEY`, `OPENROUTER_MODEL`을 설정하고 저장소 루트에서 실행한다. 키를 명령행 인자나 결과 파일에 넣지 않는다. 실제 API 비용이 발생하며 결과 파일에는 합성 입력에 대한 응답만 저장한다.

```bash
.venv/bin/python -m unittest tests.test_free_talk_api
.venv/bin/python -m unittest discover -s tests
.venv/bin/python scripts/evaluate_memory_quality.py --cases docs/tasks/LAN-454/quality-cases.json --output /tmp/lan454-quality.json --runs 2
.venv/bin/python scripts/evaluate_memory_quality.py --cases docs/tasks/LAN-454/holdout-cases.json --output /tmp/lan454-holdout.json --runs 2
```

수정 전 평가는 같은 합성 사례와 스크립트를 기준 SHA의 추출 모듈에 적용했다. 추가 사례는 첫 수정 뒤 작성했고, 날짜 기대값 강화 및 대조 예시 보완에 사용됐으므로 최종 결과를 독립적인 holdout 성능으로 해석하지 않는다.

## 남은 한계와 배포 조건

- 서버의 상대 지칭 검사는 필요조건만 검사한다. 단순히 이름을 부르거나 부정·가정을 말한 경우까지 실제 참여로 증명하지 못한다. 이름 없이 `we`만 쓰는 실제 공유 대화는 보수적으로 누락될 수 있다.
- PROFILE 지속성·불확실성·날짜 근거 판단은 여전히 LLM 정책이다. 모든 오기억을 결정적으로 차단한다고 주장하지 않는다.
- 불명확한 발화에서는 형제관계의 세부 정보가 축약될 수 있다. 자동 통과 사례도 전체 의미가 정확하다는 뜻이 아니다.
- 날짜 불명 과거 EVENT의 제외 기준 미충족과 공개 소식의 기억 저장 범위를 해결하고 검증하기 전에는 main 병합·배포하지 않는다. 이는 8/10 결과의 엄격한 기대값 미충족이며, 최종 응답에서 공개일을 시청일로 날조한 사례가 다시 관측됐다는 뜻은 아니다.
- 새 코드가 기존 `memory-candidate-v6` 기억을 소급 수정하지 않는다. 기존 기억의 문맥 재검수와 정리는 별도 승인 범위다.
- 배포 버전 후보는 `1.3.1`이다. 실제 배포 직전에 최신 태그를 다시 확인해야 한다. USE는 별도 품질 검수 전까지 false를 유지한다.

## 추가 검증 (2026-09-07)

- 새 날짜·저장 범위 사례 8개에서 수정 전 5/8 자동 통과. 공개일을 시청일로 옮기는 오류, 공개 소식 저장, UTC 날짜로 '어제'를 계산하는 오류를 재현했다 (`date-scope-before.json`). 이전 8/10 평가 당시와 달리 이번 실행에서는 공개일 전이도 다시 관측됐다.
- `_candidate_user_prompt`가 발화 시각을 요청 IANA 시간대로 변환한 뒤 LLM에 전달한다. 원래 순간과 요청 객체를 보존하며 공개 DTO는 바꾸지 않는다. 서울 자정·LA 날짜 경계 하위 테스트 2개가 수정 전 실패하고 수정 후 통과했다.
- 저장 적격성의 우선순위와 대조 예시를 두 차례 실험했으나 각각 13/16 통과에 그쳤다. 날짜 추론 오류, 티켓 PROFILE, 정상 행사 누락 또는 형제관계 축약이 관측돼 실험 프롬프트는 제외했다. 원래 v7 추출 프롬프트를 유지하며 시간대 변환만 추가했다.
- 최종 코드의 날짜·범위 사례는 8개 × 2회 중 10/16 자동 통과 (`date-scope-after.json`). 서울·LA 날짜 경계는 4/4 통과. 실패 6건은 날짜 불명 시청 2회, 공개 소식 저장 2회, 날짜 불명 방문 1회, 여동생을 동생으로 축약한 1회다. 이 결과는 이전 기본 32/32·추가 8/10과 별도 평가이며 전체 품질 통과를 의미하지 않는다.
- 평가기는 실제 서비스와 같은 사용자 프롬프트 생성 함수를 사용하고, 한글 날짜 표기를 정규화한 뒤 날짜·validFrom의 동일 순간을 검사한다. 후보 수/표현 검사는 여전히 의미 검수의 대체물이 아니다. 합성 응답은 수동으로도 확인했으며, 이 사례는 개선에 사용됐으므로 독립 holdout으로 주장하지 않는다.
- 최종 전체 unittest 473개 실행·7개 skip·실패 0개. 프리톡 관련 138개 통과. `compileall`, `pip check`, `git diff --check` 통과. BE는 변경하지 않아 Gradle 검증을 다시 실행하지 않았다.
- 다음 수정은 같은 프롬프트 예시를 계속 늘리기보다, 사건별 원문 근거를 구조화해 판정·검증하는 방법을 검토해야 한다. 추가 호출/계약 비용과 정상 기억의 누락을 함께 평가하기 전에는 해결 완료로 표시하지 않는다.
