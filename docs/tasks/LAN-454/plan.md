## v8 구현 및 검증 기록

## 해결 방법

1. USER 원문에 상대 지칭조차 없는 캐릭터 추가 후보를 임베딩 전에 제거한다. 캐릭터는 청자이며 현실 사건의 참여자로 자동 추가하지 않는다.
2. 일회성 행동·불확실한 자기평가·미확인 건강 추측을 지속적인 PROFILE로 확정하지 않는다. 확정된 습관·관계·목표는 보존한다.
3. 발화 시각을 요청 IANA 시간대로 변환해 동일 순간을 현지 날짜로 표현한다. 서울 자정과 LA 날짜 경계를 검사한다.
4. 후보가 있으면 원문과 후보 전체를 한 번 더 LLM에 전달해 개인적 사실 여부, 해당 행동의 날짜 근거, PROFILE의 지속성을 각각 판정한다. 부적격 후보는 제외하고 검증된 후보만 임베딩한다.
5. 관계·참여자 번역 보완은 인용한 USER 메시지가 해당 후보의 출처인지와 실제 원문 부분 문자열인지 검사한다. 날짜·수치·유형·유효기간·출처는 바꾸지 못한다. 동일 발화의 명확한 대명사 연결은 허용하되 날짜를 다른 행동으로 옮기지는 않는다.
6. 한국어의 일반적인 `동생` 보완은 출처에 `my younger sister/brother` 또는 `내/제 여동생/남동생`이 명시되고 다른 형제·사촌·친구 언급이 없을 때만 한다. 문장 첫머리의 사용자·절대 날짜 뒤 독립적인 동생만 바꾸며, 사촌동생·친구의 동생·아내 동생은 자동 치환하지 않는다.
7. 추출과 원문 대조에만 `medium` 추론과 `max_completion_tokens=4096`을 적용한다. 일반 프리톡 생성 호출은 기존 옵션을 유지한다.

현재 후보의 근거 판정은 내부 계약이다. 기존 BE 요청이 이미 원문과 시각을 전달하므로 공개 API 확장은 필요하지 않았다. v8 원문 대조는 새로운 후보를 만들지 않으며, 중복·누락·알 수 없는 인덱스나 잘못된 보완 근거는 502로 거부했다. v10의 후보별 실패 격리는 아래 후속 보완에 기록한다. 호출 실패는 503이며 미검증 후보를 임베딩하지 않는다. 검증 단계에서 후보 일부가 부적격이면 나머지는 계속 처리한다.

BE의 기존 `FreeTalkMemoryGenerationService`는 비동기 기억 생성 예외를 실패 상태로 기록하고 완료된 프리톡 흐름으로 전파하지 않는다. 이번 hotfix에서 이 동작을 수정하거나 운영에서 다시 실행하지 않았다.

## 재현과 회귀 검증

- 캐릭터 오삽입·재인덱싱의 하위 사례 5개, 서울·LA 날짜 경계 2개를 수정 전 실패로 확인했다.
- 독립 리뷰에서 사촌동생·친구의 동생의 성별 오치환을 발견했다. 범위를 좁히면서 드러난 독립 `동생의 결혼식`, 날짜 뒤 동생, 소유격이 생략된 `아내 동생`도 각각 red → green으로 확인했다.
- 독립 리뷰는 읽기 전용으로 수행했다. 구현은 메인 세션에서 했으며 최종 소유자 검사에서 추가 차단 결함이 발견되지 않았다.
- unittest의 LLM·embedding은 mock이다. API 기존 검사는 원문 대조를 별도로 격리하고, 새 모듈 테스트는 추출 → 원문 대조 → 임베딩의 실제 호출 순서와 실패 경계를 mock으로 검증한다.
- 실제 모델은 OpenRouter `openai/gpt-5.4-mini`, temperature 0, 공급자 라우팅 비고정이다. 운영 원문을 복사하지 않은 합성 발화만 전송했다. 실제 평가기는 서비스와 같은 추출·원문 대조 경로를 사용하며 embedding·DB 저장·일반 대화 생성은 호출하지 않는다.
- 자동 검사는 후보 수·유형·필수/금지 표현·EVENT의 날짜와 관계 표현을 검사한다. 전체 의미 정확도나 운영 Precision을 계산하지 않는다. 평가 출력은 원문과 수동으로도 대조했다.

## 재실행

외부에서 `OPENROUTER_API_KEY`, `OPENROUTER_MODEL`을 설정한다. 키를 명령행 인자나 결과 파일에 넣지 않는다. 실제 평가에는 API 비용이 발생한다.

```bash
.venv/bin/python -m unittest tests.test_free_talk_api tests.test_memory_candidate_review tests.test_free_talk_json_completion
.venv/bin/python -m unittest discover -s tests
.venv/bin/python scripts/evaluate_memory_quality.py --cases docs/tasks/LAN-454/date-scope-cases.json --output /tmp/lan454-date.json --runs 2
```

나머지 25개는 아래 순서로 합친 뒤 같은 평가기로 실행한다. 이 직렬화 형식과 순서가 최종 결과의 cases SHA-256 기준이다.

```bash
.venv/bin/python - <<'PY'
import json
from pathlib import Path
root = Path('docs/tasks/LAN-454')
names = ['quality-cases.json', 'holdout-cases.json', 'validation-cases.json']
cases = sum([json.loads((root / name).read_text()) for name in names], [])
Path('/tmp/lan454-cases.json').write_text(json.dumps(cases, ensure_ascii=False, indent=2) + '\n')
PY
.venv/bin/python scripts/evaluate_memory_quality.py --cases /tmp/lan454-cases.json --output /tmp/lan454-regression.json --runs 2
```

평가 기준도 수정했다. 명시된 부모·형제관계는 기존 정책상 안정적인 PROFILE이므로 관련 가족 사례에서 EVENT와 PROFILE의 공존을 허용한다. 대신 EVENT 자체에 관계 표현이 있는지와 EVENT 날짜를 별도로 검사한다. 공개 소식·날짜 불명 사건·불확실한 사실의 제외 기준은 완화하지 않았다. 이전 결과의 해시는 당시 커밋의 fixture 기준이며 현재 fixture와 직접 비교해 개선율을 산출하면 안 된다. 모든 사례는 개선에 사용됐으므로 독립 holdout 성능으로 주장하지 않는다.

## 비용과 남은 한계

- 후보가 있을 때 추출 요청당 LLM 호출이 한 번 추가된다. 빈 후보는 대조·임베딩을 건너뛴다. 추론 토큰도 비용이 발생하며 `exclude=true`는 추론 비활성화가 아니다. [OpenRouter reasoning 문서](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens).
- 모델의 원문 판정과 보완 문장의 의미까지 결정적으로 증명하지는 못한다. 인용 부분 문자열·불변 날짜/수치 검사는 구조적 근거 검사이며 인용이 문장 전체를 함의하는지까지 코드가 증명하지 않는다.
- 같은 불완전 발화도 모델 실행에 따라 후보 수·세부 정보가 달라질 수 있다. 예전 동급생과 4년 만에 만났다는 기간이나 일부 동행 정보가 축약된 사례가 있다. 자동 검사는 모든 세부 정보의 보존율을 측정하지 않는다.
- 소규모 합성 평가의 지연은 추출·대조만 포함한다. 운영 부하·embedding·DB·SDK 재시도에 따른 총 지연과 비용은 별도 측정이 필요하다. 일반 대화의 timeout을 늘리지는 않는다.
- 새 코드가 기존 v6 기억을 소급 수정하지 않는다. 운영 36개 기억의 정리·USE 활성화·실제 대화 효과 검증은 별도 단계다.
- 배포 버전 후보는 `1.3.1`이며 실제 배포 직전 최신 태그를 다시 확인해야 한다. 이번 작업에서 배포하지 않았다.

## v10 후속 보완 (2026-09-09)

최신 main `ee17e28`에서 LAN-454 hotfix를 이어 진행했다. 위 배포 후보와 v8 검증 수치는 과거 기록이다. 이번 변경은 AI 후보 추출·대조에 한정하며, 공개 DTO·BE·USE 설정·운영 DB는 변경하지 않았다.

### 확인한 문제와 변경

- 운영 FAILED의 확인 가능한 오류는 `candidate refinement requires source evidence`였다. 당시 모델 원응답이 없으므로 인용 불일치·출처 ID·수치 변경 중 무엇이 원인인지는 확정하지 못했다.
- 잘못된 REFINE 하나가 정상 후보까지 실패시키는 경로를 mock으로 재현했다. 이제 해당 후보만 제외하고 정상 후보를 계속 임베딩한다. 정확한 USER 인용, 후보 출처 ID, 날짜·수치 불변 조건은 유지한다. 잘못된 응답 구조·중복·누락 인덱스는 여전히 전체 요청을 실패시킨다.
- 모든 후보의 보완 근거가 잘못되면 성공 응답의 빈 후보가 될 수 있다. `workflow=memory_candidate_review reason=invalid_refinement_evidence` 경고로 구분하며 원문·보완 문장은 로그에 남기지 않는다. READY이고 DB 기억이 없다는 사실만으로 추출이 처음부터 비었다고 단정할 수 없다. 대조 DROP·resolution IGNORE·기존 데이터 삭제도 구분해야 한다.
- 종료 인사 정규식이 동일 발화의 취미까지 제거하는 결함을 재현했다. 이 정규식을 제거하고 원문 대조가 후보별로 종료 인사와 독립 사실을 구분하도록 했다. 순수 종료 인사의 제외는 이제 모델 판단이므로 mock 검사와 실제 합성 평가를 별도로 수행했다.
- 선호의 대상·공부 목적을 각 기억 문장에 보존하고, 선호를 실제 생활 습관으로 확정하지 않도록 지시했다. 같은 사건을 후속 발화로 명확히 하는 경우 날짜 근거가 있는 USER 메시지도 함께 인용하도록 보완했다. 다른 사건의 날짜를 가져오는 것은 계속 금지한다. extractorVersion은 `memory-candidate-v10`이다.

### 검증 결과

- 재현 테스트에서 잘못된 보완 4종과 종료 인사 혼합 사실 1종이 수정 전 실패했다. 수정 후 관련 unittest 158개, 전체 504개 실행·7개 skip·실패 0개다. `compileall`, `pip check`, `git diff --check`도 통과했다. BE 변경이 없어 Gradle은 다시 실행하지 않았다.
- 읽기 전용 독립 리뷰에서 병합 차단 결함은 없었다. 리뷰가 지적한 순수 종료 인사 검증 공백은 영어·한국어 합성 사례 3개 × 2회로 보완했고 6/6 빈 후보였다.
- OpenRouter `openai/gpt-5.4-mini`를 사용하는 실제 추출·대조 평가다. 운영 원문을 재전송하지 않은 합성 발화이며 embedding·resolution·DB 저장은 호출하지 않았다.
