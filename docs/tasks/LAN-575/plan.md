# LAN-575 기억 후보 출처 오류 교정

## 문제와 결정

- 기준: `origin/main`의 `a074b46`. 운영 AI-PROD-M은 기억 후보의 출처가 요청의 USER 메시지로 확인되지 않아 실패했다. 기존 진단만으로 없는 ID와 AI 메시지 ID를 구분할 수는 없다.
- 출처 검증을 완화하지 않는다. 허용된 USER ID 목록을 프롬프트에 명시하고, 이 검증에 실패한 경우에만 원문에서 후보 전체를 한 번 재생성한다. 서버가 ID를 임의로 치환하지 않는다.
- 교정 응답에도 언어·인덱스·출처 검증, 기존 필터와 원문 대조를 적용한다. 올바른 ID라는 사실만으로 의미적 근거가 확인되는 것은 아니다.
- 초기 JSON 호출의 최대 2회 시도는 유지한다. 출처 교정은 `max_attempts=1`이며 별도 JSON 재시도를 하지 않는다. 출력 한도 소진도 재시도하지 않는다. 포맷 미지원 전환은 기존대로 가능하다.
- 전체 외부 호출 예산 50초·최대 9회, 개별 호출 상한 20초를 공유한다. 모델·추론 강도 `low`·생성 한도 4096은 유지한다. 추가 교정에는 토큰 비용이 들며 예산을 사용하면 뒤의 원문 대조나 임베딩이 실패할 수도 있다.
- `CompletionAttempts`를 호출자에게 전달할 수 있게 하여 JSON 이후 출처 검증까지 기록한다. 실패가 있으면 최초 실패, 각 HTTP 시도와 제공된 종료 사유·토큰·generation/request ID·시간을 WARNING 로그에 남긴다. 원문과 시크릿은 포함하지 않는다.
- 교정 실패는 `free_talk_memory_candidates / source_validation / candidate_source_correction_failed`로 분류한다. 관측의 `attempt=2`는 교정 단계이며 실제 HTTP 횟수는 진단의 attempts로 확인한다.
- 추출 정책 버전은 `memory-candidate-v12`. BE 및 public API 스키마 변경은 없다.

## 구현과 검증

1. 수정 전 6개 테스트로 교정 부재와 진단 누락을 재현했다. subtest 포함 7개 assertion 실패와 2개 예외가 발생했다.
2. 최소 교정 경로와 호출자 소유 진단을 추가했다.
3. 회귀 검증 결과:
   - AI ID, 없는 ID, 정상·잘못된 ID 혼합 → 한 번 교정 후 동일 계약으로 검사한다.
   - 반복 출처 오류 → 502이며 원문 대조·임베딩·후속 질문을 호출하지 않는다.
   - 교정 후 다른 계약 위반, 빈 응답, 출력 한도 소진 → 추가 교정 없이 실패한다. 정상 빈 후보 배열과 구별한다.
   - 출처가 교정되어도 고정 원문 대조 응답이 DROP이면 후보를 반환하지 않는다.
   - 시간 소진 후 새 교정 요청이 전송되지 않는다. 로컬 HTTP에서도 호출 상한 1회 설정 시 두 번째 요청이 서버에 도달하지 않는다.
   - 로컬 HTTP: 최초 응답 120ms 지연, 교정 응답 700ms 지연, 공유 예산 400ms에서 실패하고 700ms 검사 상한을 만족했다. 이 값은 테스트 조건이며 운영 지연 실측이 아니다.
   - 출처 실패 후 provider 오류가 나도 최초 실패와 첫 호출의 토큰·종료 정보가 WARNING에 남는다. 진단 누락 및 원문·시크릿 미포함도 검증했다.
   - 관련 테스트 182개 통과. 진단 소유권 테스트를 포함한 최종 전체 unittest 829개 실행, 822개 통과·7개 skip.
   - OpenAPI 전후 동일, `git diff --check` 통과.

## 검증 환경과 한계

- 최초 기준 검증은 기존 가상환경의 `tiktoken` 누락으로 실패했다. pyproject의 고정 버전 0.12.0을 설치했고 로컬 HTTP 바인딩 및 토크나이저 사전 다운로드 권한을 확보해 검증했다.
- main의 별도 원본에서 818개를 실행했을 때 남은 2개 오류는 아카이브에 Git 메타데이터가 없었기 때문이다. 실제 저장소의 Git 메타데이터를 지정한 재실행에서 두 테스트 모두 통과했다.
- 검증은 고정 모델 응답 및 로컬 HTTP 기반이다. 실제 모델의 교정 성공률, 의미적 품질, 비용 및 운영 성공률은 측정하지 않았다.
- 잘못된 후보는 AI 응답으로 반환하지 않는다. BE 저장·대화 완료 상태는 이번에 변경하거나 운영 DB에서 재검증하지 않았다.
- 과거 실패 작업 재처리, push, PR, 배포는 이번 작업에 포함하지 않았다.
