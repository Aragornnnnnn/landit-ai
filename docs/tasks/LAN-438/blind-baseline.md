# LAN-438 온보딩 수준 평가 블라인드 baseline

> 이 문서의 기존 60회 결과는 피드백과 수준 평가를 함께 생성하던 경로의 측정이다. 현재 독립 `session-level-assessment` 경로의 결과는 마지막 「독립 수준 평가 경로 재측정」을 참고한다.

## 결론

현재 상태는 출시 기준을 통과하지 못한다.

- 유효한 제품 평가 9건은 모두 독립 기준 범위 안에 들었다.
- 그러나 최초 실행 40건 중 31건이 최종 평가 JSON 형식 오류로 실패했다.
- BE fallback을 적용하면 결제 흐름의 HTTP 응답은 유지되지만, 해당 31건은 `FALLBACK`·`NOT_APPLIED`가 되어 실제 사용자 수준을 확정하지 못한다.
- 따라서 지금 고칠 최소 범위는 평가 프롬프트·가중치·임계값이 아니라 최종 Core JSON 생성·복구 경계다.

## 실행 역할

| 역할 | 대상 | 사용 범위 |
| --- | --- | --- |
| 실행 주체 | Codex 에이전트 | 데이터셋 준비, 호출 실행, 결과 집계, 보고서 작성. 평가 라벨을 생성하지 않음. |
| 제품 평가 모델 | `openai/gpt-5.4-mini` | 실제 `session-feedback` 수준 평가. |
| 턴 피드백 모델 | `openai/gpt-5.4` | 실제 message-feedback 4회. 검수 모델 비활성. |
| 독립 기준 평가 모델 | `google/gemini-3.5-flash` | 제품 결과와 작성 목표를 보지 않고 허용 수준 범위 작성. 사람 정답이 아닌 `model_reference`. |

제품 평가는 현재 develop 설정과 제품 코드를 사용했다. 독립 기준 모델은 제품 평가 모델과 분리했다.


60개 전체를 BE HTTP와 DB로 다시 호출하지는 않았다. 실제 AI 함수와 캐시를 한 프로세스에서 실행하고, BE 계산은 동일 상수와 수식으로 재현했다. BE 저장·응답 경계는 격리 H2 통합 테스트로 별도 검증했다. 따라서 이 결과는 모델 baseline에는 유효하지만, 60개 세션 전체 E2E 성능 측정으로 해석하면 안 된다.

- 반복 표본 10개 중 3회 모두 유효한 결과를 받은 대화: 0/10.

평가 값 자체의 흔들림보다 형식 실패가 반복성 검증을 먼저 막았다.

### 5. 형식 실패

- 총 제품 세션: 60.
- 제품 모델 호출: 300회. 턴 피드백 240회, 최종 평가 60회. 독립 기준 평가 40회를 포함한 전체 호출은 340회다.
- 제품 성공: 15/60.
- 최종 평가 실패: 45/60, 75%.
- 실패 45건 모두 `AiGenerationFailedError`와 invalid JSON이었다.
- JSON 파서 기준 39건은 끝부분 구분자·닫힘 부족, 6건은 객체 키 형식 오류였다.
- 300회 모두 provider 종료 사유는 `stop`이었다. 실패 응답의 completion은 685~1,155 tokens여서 현재 2,048 token 제한 도달에 따른 잘림으로 보이지 않는다.

AI 직접 호출에서는 오류가 반환된다. 실제 BE는 이 오류 코드를 잡아 fallback 결과를 저장하므로, 같은 45건은 `FALLBACK`·`NOT_APPLIED`가 되고 사용자 수준과 streak를 바꾸지 않는다.

## BE fallback 및 불변조건

격리 H2 통합 테스트에서 다음을 확인했다.

- 최종 AI 생성 실패에도 세션 피드백 API가 HTTP 200을 반환한다.
- 응답·저장 source는 `FALLBACK`, 변경 유형은 `NOT_APPLIED`다.
- 미설정 `learning_level`과 promotion streak를 변경하지 않는다.
- 같은 세션 피드백 재요청은 AI를 다시 호출하거나 요약·메시지·수준 평가 행을 중복 생성하지 않는다.
- 일부 영역 미관찰 Core는 저장하되 수준을 초기화하지 않는다.
- Details가 유효하지 않아도 Core를 유지하는 AI 테스트가 통과한다.
- 표현 조회는 현재 프로필의 `learning_level`을 콘텐츠 그룹으로 변환한다. 세션 평가 저장과 표현 조회는 각각 통합 테스트를 통과했지만, 한 HTTP 시나리오로 연결한 단일 테스트는 아직 없다.

오류별 개별 네트워크 주입(timeout, AI 5xx, malformed Core, cache mismatch)을 하나의 E2E 표로 재실행하지는 않았다. 기존 AI·BE 테스트 묶음은 해당 파싱·생성 실패와 fallback 경계를 검증한다. 이 항목은 baseline의 제한으로 남긴다.

## 판단

### 수준 구분 가능 여부

유효 JSON에 한해서는 5개 영역과 종합 수준이 독립 기준과 1단계 이내로 일치했다. 그러나 유효율이 25%라 현재 제품 흐름에서 안정적으로 수준을 구분한다고 말할 수 없다.

### 가장 큰 실패 원인

1. 최종 수준 평가 JSON 형식 실패 45/60.
2. 그 결과 최초 수준 확정 차단 24/30 정상 대화.
3. 반복 표본 10개 모두 3회 완주에 실패해 반복성 판단 불가.

### 다음 수정의 최소 범위

1. 최종 `session-feedback` 응답에 구조화 출력 또는 제한적인 JSON 닫힘 복구를 적용한다.
2. 복구 후에도 Core의 메시지 ID, 5개 영역, 근거 원문 포함 여부는 현재처럼 엄격히 검증한다.
3. 같은 봉인 데이터는 개선용으로 재사용하지 않는다. 수정 후 신규 holdout으로 다시 측정한다.
4. 형식 유효율을 먼저 확보한 뒤에만 루브릭·가중치·임계값 조정을 검토한다.

이번 baseline에서는 위 개선을 적용하지 않았다.

## 남은 검증

- 영어 교육 전문가 또는 복수 사람 평가자의 기준표.
- 실제 사용자 음성 전사에서 생기는 STT 오류를 포함한 평가.
- 신규 holdout에서 형식 유효율, 수준 일치도, 반복성 재측정.
- 성공 평가 직후 같은 사용자로 표현 GET까지 이어지는 단일 BE 통합 테스트.
- 로컬 BE·AI HTTP 전체 경로의 지연과 timeout 예산.

## 후속 형식 안정화 회귀

baseline 결과를 보존한 채 JSON 생성 경계만 수정하고, 2026-09-06에 같은 조건의 제품 평가 60회를 다시 실행했다. 평가 프롬프트·루브릭·가중치·임계값은 변경하지 않았다.

### 가용성

| 항목 | baseline | 형식 안정화 후 |
| --- | ---: | ---: |
| 전체 유효 Core | 15/60, 25% | 59/60, 98.3% |
| 첫 실행 유효 Core | 9/40, 22.5% | 39/40, 97.5% |

### 판단

- 형식 유효율과 반복성은 잠정 출시 기준을 통과했다.
