# LAN-567 레벨 평가 출력 예산과 실패 진단 개선

## 승인된 범위

- main 기반 hotfix. 레벨 평가 출력 한도 소진 처리와 최초 검증 실패 진단을 개선한다.
- 기존 인용 검증 교정, 점수·승급·FALLBACK, public DTO를 유지한다.
- 메모리 생성, 과거 작업 재처리, provider 입출력 본문 저장은 제외한다.

## 확인된 원인

- 운영 AI 8ba7010, 세션 6855. 최초 생성은 1213토큰·completed였으나 검증 탈락 사유는 남아 있지 않다.
- Core 재시도는 1536토큰·추론 0토큰, native_finish_reason=max_output_tokens로 종료되어 JSON 파싱에 실패했다.
- I/O 저장이 비활성화되어 과거 최초 응답의 정확한 탈락 사유는 복원할 수 없다.

## 구현 정책

- 초기 평가와 Core 재시도에 같은 입력 기반 예산을 적용한다. 메시지마다 다섯 영역에 전체 사용자 발화를 인용하는 JSON 크기를 o200k_base로 계산하고 25% 여유와 envelope/Details용 512토큰을 더한다.
- 최소 2048, 최대 16384토큰이다. 고정 1536토큰 축소를 제거하면서 긴 발화·다수 메시지를 고려하고 비용 상한을 둔다. 이 추정은 모든 표현 길이와 임의 입력을 보장하지 않는다. 한도 도달 시 검증된 모델 결과로 사용하지 않는다.
- 기존 100초 전체 평가 deadline, BE 평가 전용 120초 timeout을 유지한다. SDK 재시도는 0회이며 남은 시간을 호출 timeout으로 사용한다. 최초 출력 형식 호환 시도는 최대 3회, Core 교정은 최대 1회로 provider 호출은 최대 4회다.
- level-assessment 요청 범위의 ContextVar에 실제 호출과 검증 실패를 보존한다. format 호환 호출도 별도 순번으로 기록한다. 본문·예외 문자열·임의 header는 기록하지 않는다.
- 알려진 종료 사유와 제한된 ID, 정수 토큰 사용량만 기록한다. 누락된 진단값은 null이다. 출력 한도 도달은 completion_output_limit로 구분하고 JSON 파싱 전에 거부한다.
- 최초/재시도 검증 사유는 원문 없는 코드·필드 경로로 같은 로그에 남긴다. 기존 Sentry 최종 실패 정책을 유지한다.

## 검증 계획

1. 출력 한도 도달, 메타데이터 누락·오염, 최초/최종 실패 보존 및 요청 간 격리를 검증한다.
2. 다수 메시지와 긴 인용문을 가진 합성 평가 JSON으로 예산과 실제 파서·정합성 검증을 확인한다.
3. 로컬 지연 HTTP 서버로 남은 timeout, 추가 재시도 방지, 호출 상한을 확인한다.
4. AI 전체 unittest, OpenAPI 불변 비교, BE fallback 관련 기존 테스트를 확인한다.
5. 로컬 합성·mock 결과와 실제 LLM 품질·지연·비용·운영 성공률을 구분한다.

## 검증 결과

- AI `.venv/bin/python -m unittest discover -s tests`: 802개 실행, 성공, 7개 skip. 실제 LLM 호출 없이 합성 응답과 로컬 HTTP 서버로 검증했다.
- 출력 한도 종료는 빈 본문·잘린 JSON·파싱 가능한 JSON 모두 거부한다. 표준 `length`와 provider 고유 `max_output_tokens`를 각각 검증했다.
- 최초 인용 검증 실패와 재시도 출력 한도 소진을 함께 보존하며, JSON·schema·메시지 ID 오류가 서로 다른 사유로 남는다. 메타데이터 누락·오염, 요청 간 분리, 원문·시크릿 미포함을 검증했다.
- 메시지 1·3·10개와 짧은 발화·긴 인용·따옴표·줄바꿈·한글을 조합한 합성 JSON을 실제 파서와 정합성 검증에 통과시켰다. 긴 입력의 최대 16384토큰 제한도 확인했다.
- 로컬 HTTP에서 최초 지연 timeout, Core 재시도의 남은 시간 사용, SDK 추가 재시도 없음, 형식 전환을 포함한 최대 4회 호출을 확인했다.
- BE 기존 평가·FALLBACK 관련 테스트 156개 성공: `./gradlew test --tests '*LearningLevelPolicyTest' --tests '*SessionLevelAssessmentRecoveryTest' --tests '*SessionLevelAssessmentProfileTest' --tests '*ScenarioSessionApiIntegrationTests'`. BE 소스 변경은 없으며 전체 `./gradlew check`는 실행하지 않았다.
- `origin/main` 8ba7010과 OpenAPI가 동일하다. SHA-256: `d54355f09e42a78a58dd61b0f35958e8f8536cec168feabc166b09067f49e513`.
- `pip check`, `git diff --check` 성공. 최초 전체 실행의 프리톡 로그 개수 검증 실패는 단독 실행과 이후 두 차례 전체 실행에서 재현되지 않았다. 이 테스트나 프리톡 구현은 변경하지 않았다.

## 운영 확인 및 남은 한계

- 배포 후 `assessment_diagnostics` 로그를 request_id로 조회하면 호출별 stage·attempt·출력 형식·허용 토큰·사용 토큰·종료 사유·소요 시간과 최초/재시도 검증 사유를 함께 확인할 수 있다. 기존 Sentry 정책은 최종 실패만 보고하므로 전체 시도 이력은 로그에서 확인한다.
- 토큰 계산은 Core 구조와 전체 발화 인용에 근거한 추정이다. 매우 긴 입력, 모델별 토큰화 차이, 선택적 Details 길이로 한도를 넘을 수 있다. 이때 잘린 응답은 저장 가능한 평가로 반환하지 않고 기존 실패 처리를 따른다.
- 출력 상한은 실제 사용량이나 요금이 아니다. 초기·Core 재시도 각각 최대 16384토큰을 허용하므로 기존 2048/1536보다 최대 비용·지연 가능성이 커진다. 실제 LLM의 품질·지연·비용·운영 성공률 개선은 아직 검증하지 않았다.
- 기존 deadline은 남은 시간을 SDK timeout에 전달하고 늦게 도착한 응답을 거부한다. SDK의 단계별 I/O timeout이므로 바이트가 조금씩 계속 도착하는 응답까지 100초에 강제 중단하는 보장은 추가하지 않았다.
- 과거 최초 검증 실패 사유는 복원할 수 없다. 과거 작업 재처리, 병합 및 배포는 수행하지 않았다.
