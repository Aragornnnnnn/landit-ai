# LAN-209 PoC 계획 — 발음 판정 일관성 검증

Gemini 2.5 Flash(OpenRouter)가 사전 구축 기준 데이터 대비 음소·강세 오류를
**일관되게** 감지하는지 검증한다. 여기서 실패하면 `design.md`의 기준 데이터
포맷·API 스키마를 재검토한다.

## 검증 항목

1. **오류 감지 정확도** — 의도한 오발음(th→s, 강세 이동)을 잡아내는가
2. **오탐** — 정상 발음을 오류로 판정하지 않는가 (가장 위험한 실패 모드)
3. **반복 일관성** — 같은 오디오를 여러 번 판정해도 같은 결과가 나오는가
4. **스키마 안정성** — 지정한 JSON 스키마를 벗어나지 않는가

## 골든 셋 녹음 가이드

문장: `There's nothing like hiking to clear my head.`
`docs/tasks/LAN-209/audio/`에 아래 4개를 녹음한다. **wav 또는 mp3만 지원**
(아이폰 m4a는 변환: `afconvert in.m4a out.wav -d LEI16 -f WAVE`).

| 파일 | 녹음 방법 |
| --- | --- |
| correct.wav | 최대한 정확하게 발음 |
| th_to_s.wav | nothing의 th를 일부러 s로 (nuh·ssing) |
| stress_hiking.wav | hiking의 강세를 일부러 뒤 음절에 (hik·ÍNG) |
| combined.wav | 위 두 오류를 동시에 |

## 실행

```bash
.venv/bin/python scripts/poc_pronunciation.py \
    --manifest docs/tasks/LAN-209/poc_manifest.json --runs 3
```

- `.env`에 `OPENROUTER_API_KEY` 필요
- 결과는 `docs/tasks/LAN-209/poc_results/`에 JSON으로 저장됨
- 모델 비교 시 `--model`로 교체 실행

## 통과 기준 (go / no-go)

- correct 샘플 오탐률 0% (3회 모두)
- 오류 샘플의 의도한 오류 감지율 ≥ 2/3회
- 스키마 파싱 실패 없음 (재시도 1회 내 성공)

미달 시: 프롬프트 조정 → 재실행. 그래도 미달이면 판정 축소(음소만 우선) 또는
모델 교체 검토 후 design.md 갱신.

골든 셋 4개(학습자 녹음) + TTS 대조군 1개, 샘플당 3회 반복. 원본 JSON은 `poc_results/`.

| 실험 | 모델 | correct 오탐 | th→s 감지 | 강세 감지 | 반복 일관성 |
| --- | --- | --- | --- | --- | --- |
| v1 프롬프트 | gemini-2.5-flash | 3/3 (매번 다른 단어) | 2/3 | 0/3 | X |
| v2 프롬프트 (지각→판정 2단계, temp 0) | gemini-2.5-flash | 0/3 | 0/3 | 0/3 | O (전부 ok로 수렴) |
| v2 프롬프트 | gemini-2.5-pro | 2~3/3 | 3/3 | 0/3 | 부분적 |
| v2 + 원어민 TTS 대조군 | gemini-2.5-pro | **3/3** (nothing·there's를 원어민 음성에서도 오류 판정) | - | - | O |

### 핵심 발견

1. **Flash는 음소를 지각하지 못한다.** v2의 지각 단계(`heard`)가 실제 발화("nuh·ssing")
   대신 기준 표기("nuh·thing")를 그대로 반환 — ASR의 정규화 특성(틀린 발음을 올바른
   단어로 교정해 인식)이 발음 평가와 정반대로 작동.
2. **Pro는 th 오류를 3/3 잡지만, 원어민 TTS 음성에서도 같은 오류를 3/3 판정했다.**
   즉 실제 청지각이 아니라 "한국인은 th를 틀린다"는 사전 지식 기반 환각.
3. **강세 오류는 어떤 조합에서도 0% 감지.**
4. 점수(85~95)는 오류 유무와 무관하게 분포 — 93% 컷과 결합 불가.

### 추가 실험: 자유 전사 (기준 문장 미제공)

기준 문장을 주지 않고 "들리는 대로 적어라"만 지시 (앵커링 제거).

| 샘플 | 모델 | 결과 (3회) |
| --- | --- | --- |
| word_swap (nothing→everybody) | Flash·Pro | 둘 다 "everybody"로 전사 — 단어 치환 감지 O |
| th_to_s (미묘한 오발음) | Flash·Pro | 둘 다 "nothing"으로 정규화 — 감지 X |
| th_to_s2 (과장된 "나싱") | Flash | "nothing"으로 정규화 — 감지 X |
| th_to_s2 (과장된 "나싱") | **Pro** | **"nashing"×2, "nussing"×1 — 3/3 감지** |
| correct + tts_correct | Pro | 3/3 + 3/3 정상 전사 — **오탐 0** |

### 수정된 결론

1. **판정 모드(기준 제공) no-go는 유지** — 기준 문장이 프롬프트에 있으면 앵커링
   (Flash: 기준 표기 앵무새, Pro: 사전지식 기반 환각)이 발생.
2. **Pro의 자유 전사는 뚜렷한 음소 오류를 재현성 있게 감지하고 오탐이 없다.**
   → "① 자유 전사(오디오, 기준 미제공) → ② 전사 결과 vs 기준 텍스트 비교(서버/텍스트 LLM)"
   2단계 파이프라인이 유력한 대안.
3. 한계: 미묘한 오발음은 정규화되어 미감지(관대한 실패 — 오탐보다 수용 가능).
   **강세 감지는 여전히 미해결** — 자유 전사로는 강세를 알 수 없음.
   점수는 모델 출력 대신 서버가 오류 단어 수로 산출하는 방향 검토.

### 확장 검증 (v2, 2026-07-25): 문장 4개 × 유형 3종 × 2회 — go

문장 4개(th / r·l / f·p / v·b + 강세 단어 4종), 화자 1명(본인), 모델
`google/gemini-3.5-flash`. 스크립트 `scripts/poc_pronunciation_v2.py`,
원본 `poc_results/v2_20260725T045219Z_*.json`.

| 모드 | 정확일치 | 오탐 | 지연 p50 / max |
| --- | --- | --- | --- |
| transcribe (자유 전사 + 서버 비교) | 19/24 | 4 run | 5.0s / 7.8s |
| **compare (TTS 참조 오디오 대조)** | **24/24** | **0** | 5.6s / 9.0s |

- **compare 모드가 음소 4종·강세 4종 전부 2/2 감지, correct 오탐 0, 스키마 에러 0.**
  강세 감지가 재현된 것이 결정적 (transcribe는 원리상 강세 불가).
- 대조 프롬프트에 "축약·연음·목소리·속도 무시" 명시 후 이전 잡음(축약 지적) 소멸.
- 남은 한계: 화자 1명, 과장된 오류, 조용한 환경. 팀원 녹음으로 화자 일반화 확인 예정.
