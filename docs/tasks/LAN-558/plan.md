# LAN-558 Sentry 진단 정보 개선

## 승인된 범위

Sentry에서 자세한 예외 사항을 확인할 수 있도록 BE와 AI의 관측 경로를 개선한다. 사용자 응답, 모델 호출/재시도 횟수, fallback과 정상 복구/거절의 이벤트 제외 정책은 유지한다. 운영 배포는 포함하지 않는다.

추가 사용자 요청에 따라 인증된 내부 사용자 ID를 요청 컨텍스트와 Sentry `user.id`로 전달한다. 이메일·이름·IP·토큰·발화 원문은 포함하지 않는다.

## 구현

- 공통 예외 체인에서 허용된 고정 사유, Pydantic 검증 필드/종류, 외부 HTTP 상태, JSON 실패 위치와 API 오류 코드를 수집한다.
- 필드 경로는 알려진 DTO 이름만 보존한다. 임의 딕셔너리 키는 `<field>`, 배열 인덱스는 `[]`로 바꾸고 필드/오류/원인 체인 개수를 제한한다.
- Sentry `contexts.failure`와 검색 태그에 진단 정보를 남기고 최상위 예외 제목을 기능과 안전한 사유로 표시한다. 예외 원문, 입력값, provider 본문, 헤더, 프롬프트와 로컬 변수는 제외한다.
- 수준 평가의 검증 실패를 실제 예외로 보존한 후 기존 `None` 계약으로 복구한다. 마지막 실패의 구체적인 사유와 코드 위치를 최종 보고에 연결한다.
- 프리톡 교정의 코드 오류를 명시적으로 보고하며 교정 없음 응답은 유지한다. 속마음 fallback의 문제 필드는 안전한 로그에 남기며 정상 복구는 Sentry에 보내지 않는다.
- 내부 인증 토큰 미설정 시에도 유효한 UUID 요청 ID를 전달한다. 인증 거절 요청은 외부 ID를 신뢰하지 않으며, 교정 스레드에는 요청 컨텍스트를 복사한다.
- 예외 없이 생성하는 실패 보고에도 발생 코드 위치를 남긴다.
- `X-Landit-User-Id`는 내부 토큰 인증 성공 시에만 양의 Long ID로 검증하고 ContextVar에 저장한다. 토큰 미설정/인증 실패/잘못된 ID는 사용자 정보 없이 처리한다.
- 요청과 프리톡 교정 스레드의 사용자 컨텍스트를 격리하고 요청 종료 시 복원한다. 외곽 예외 처리기가 실행될 때도 예외에 보존한 ID를 우선하여 다른 컨텍스트로 덮어쓰지 않는다.
- Sentry에는 `user.id`만 남긴다. 사용자 ID는 메트릭 차원과 오류 그룹화 지문에는 추가하지 않는다. 사용자 요청과 관계없는 작업은 사용자 ID 없이 기록한다.

## 이벤트 예시

수준 평가의 근거 불일치 시 제목은 `level_assessment: assessment_evidence_mismatch`, 태그는 `reason=core_missing`, `validation_reason=assessment_evidence_mismatch`, `attempt=2`로 기록한다. `contexts.failure.invalid_fields`에는 `core.messages.[].domains.grammar.evidenceExcerpt` 같은 경로만 남고 발화/근거 원문은 포함하지 않는다.

## 검증 결과

- 전체 `python -B -m unittest discover -s tests`: 774개 중 767개 통과, 7개 기존 조건부 제외, 실패/오류 없음. 기존 b420 작업 트리의 Python 가상환경에서 이 작업 트리의 코드를 실행했다.
- 신규 9개 테스트로 검증 메타데이터/HTTP 429/실제 스택 보존, 임의 필드명/원문 제외, 최종 수준 평가 실패, 교정 결함 단일 보고, 요청 ID 전파를 검증했다.
- 추가 7개 테스트로 인증된 ID 보존, PII 제외, 인증 미설정/실패/유효하지 않은 ID 제외, 동시 요청/교정 스레드 격리, 외곽 예외 처리 후 ID 보존, 메트릭 차원 제외를 검증했다.
- 실제 SDK와 메모리 transport를 사용했으며 운영 Sentry나 LLM에 전송하지 않았다.
- API 응답과 DB 스키마 변경 없음. 운영 이벤트의 추가 정보는 이 변경 배포 후 발생한 이벤트부터 확인할 수 있다. 과거 이벤트의 제거된 상세 정보는 복원되지 않는다.
- 새 오류 사유/DTO 필드는 진단 허용 목록을 함께 검토해야 한다.
